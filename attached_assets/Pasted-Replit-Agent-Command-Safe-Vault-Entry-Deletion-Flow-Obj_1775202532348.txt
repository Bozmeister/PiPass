Replit Agent Command — Safe Vault Entry Deletion Flow
Objective
Replace the current instant-delete vault entry behaviour with a multi-stage secure deletion flow suitable for a production password manager and App Store submission.

The current behaviour deletes a vault entry immediately when the delete button is pressed inside EntryDetailModal. This is unacceptable and must be completely replaced.

Implement a 4-stage destructive action flow + optional undo snackbar.

This change must NOT break encryption, vault storage, auto-lock, or modal navigation.

High Level Behaviour To Implement
Deleting a vault entry must now require:

Access via overflow menu (not visible red button)

First confirmation Alert dialog

Fresh biometric authentication

Final “type DELETE to confirm” modal

Delete entry

Show 10-second UNDO snackbar

The user must never be able to accidentally delete an entry.

Search and update all relevant areas.

Create new component:

components/DeleteEntryModal.tsx

PART 1 — Remove Dangerous Immediate Delete
Inside EntryDetailModal:

• Find the existing delete button that deletes the entry immediately
• REMOVE the direct deletion call
• The delete button must no longer call vaultWorker.deleteEntry() directly.

Replace the delete button with an overflow menu (•••).

If no overflow menu exists, create a simple one using a small modal or action sheet.

Menu options:

Edit Entry (existing functionality)

Delete Entry (new safe flow trigger)

The red delete button must no longer appear in the main content area.

PART 2 — First Confirmation Alert
When user taps Delete Entry from the overflow menu:

Show React Native Alert:

Title:
Delete entry?

Message:
This will permanently delete this vault item from this device and from sync.

Buttons:

Cancel (style: cancel)

Delete (style: destructive)

DO NOT delete yet.

The destructive button must call a new function:

beginSecureDeleteFlow(entryId)

PART 3 — Require Fresh Biometric Authentication
Inside the new beginSecureDeleteFlow function:

Import the existing biometric gate:
requireFreshBiometric()

Flow:

if biometric fails -> STOP
if biometric succeeds -> open DeleteEntryModal
Important:
This MUST use the existing biometric gate and respect its 2-second freshness window.

components/DeleteEntryModal.tsx

PART 5 — Final Deletion Execution
When user presses "Permanently Delete":

Call a new handler passed via props:
onConfirmDelete(entryId)

Close the modal afterwards.

Error handling must use try/catch and show an Alert on failure.

PART 6 — Implement Deletion + Undo Snackbar (VaultScreen)
Inside VaultScreen.tsx implement a temporary undo system.

Add state:

recentlyDeletedEntryRef
undoTimerRef
showUndoSnackbar
Deletion flow must now be:

Store deleted entry in memory temporarily

Remove entry from vault state immediately

Show snackbar at bottom:

Text:
"Entry deleted"

Button:
"UNDO"

Start 10 second timer

After 10 seconds permanently commit deletion

If user taps UNDO before timer:

Restore entry to vault

Cancel timer

Hide snackbar

Important:
Actual permanent deletion in storage must happen ONLY after timer expires.

PART 7 — Storage Worker Update
Add a new method in vaultWorker.ts:

permanentlyDeleteEntry(entryId)

This performs the real encrypted storage deletion.

The existing delete logic should be moved here if needed.

VaultScreen should call this ONLY after undo window expires.

• App auto-locks during undo window → cancel undo and permanently delete
• App closes during undo window → permanently delete on next launch
• Multiple rapid deletions → only track last deleted entry
• No crashes if biometric not available (web fallback already exists)
