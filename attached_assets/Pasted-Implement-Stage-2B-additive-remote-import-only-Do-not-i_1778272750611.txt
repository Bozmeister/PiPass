Goal:
When local vault is non-empty and remote has additional entries/notes, detect remote-only items and let the user explicitly import them. Never overwrite or delete local data.

Required behaviour:

1. After successful local unlock and backend login, fetch remote vault metadata/blob only if needed.
2. Use getSyncVersion() to skip work when server version <= lastSyncedVersion.
3. If no remote blob, do nothing.
4. If local vault is empty, keep existing Stage 2A restore behaviour.
5. If local vault is non-empty:

   * decrypt remote blob using existing blob key logic.
   * validate payload fully before any UI or storage write.
   * compare remote entries/notes against local entries/notes by id.
   * remote-only entries/notes become import candidates.
   * same-id identical ciphertext/salt are treated as duplicates and skipped.
   * same-id different ciphertext or salt are conflicts and must not be imported automatically.
6. Show a user confirmation UI before importing remote-only candidates.
7. UI must clearly say:

   * local vault will not be overwritten
   * only selected remote-only items will be imported
   * conflicts are skipped
   * deleted items may appear again until deletion sync/tombstones are implemented
8. On user approval:

   * re-check candidate IDs still do not exist locally before writing.
   * save only approved remote-only entries/notes.
   * saveSyncVersion(remoteVersion) only after successful local import.
   * call syncVaultToBackend(keyShares) best-effort after import to upload the merged local state.
   * trigger VaultScreen reload after successful import.
9. On cancel, malformed payload, wrong key, network error, 401, 403, or 409:

   * do not modify local vault.
   * do not block unlock.
   * do not clear local vault.
10. Do not implement tombstones.
11. Do not propagate deletions.
12. Do not auto-resolve conflicts.
13. Do not overwrite existing local entries or notes.
