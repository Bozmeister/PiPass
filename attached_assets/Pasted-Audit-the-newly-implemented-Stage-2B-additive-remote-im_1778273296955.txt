Audit the newly implemented Stage 2B additive remote import feature. Do not implement new features.

Context:
Stage 2B has just been implemented:

* lib/vaultSync.ts added planVaultMerge() and applyVaultImport()
* app/(tabs)/index.tsx now branches after backend login:

  * empty local vault → Stage 2A restore
  * non-empty local vault → Stage 2B merge planning
* screens/VaultScreen.tsx now shows an Alert with remote-only candidates and conflict count
* Approval calls applyVaultImport and reloads the vault
* Tombstones are not implemented
* Automatic overwrite/delete is forbidden

Goal:
Prove Stage 2B cannot overwrite or delete local data, cannot silently import conflicts, and does not block normal vault access.

14. Verify VaultScreen reload happens only after successful import.
15. Verify no encryptedBlob, authHash, passwords, salts, recovery keys, headers, or key material are logged.
16. Verify TypeScript remains clean.
17. Run practical tests where possible:
